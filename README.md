# SubTrack — Управление подписками (Full-Stack)

Веб-приложение для централизованного отслеживания, анализа и управления регулярными цифровыми подписками на **React + Node.js + SQLite**.

Разработано в рамках цикла лабораторных работ по дисциплине **«Frontend-разработка веб-приложений» / «Full-stack разработка»**.

## ✨ Что нового в обновлении (Было → Стало)

Проект переведён из статического клиентского прототипа (`React + localStorage`) в полноценное **Full-Stack приложение** с собственным сервером, базой данных и защищённой авторизацией:

| Область | Было | Стало |
| :--- | :--- | :--- |
| **Хранение данных** | Массив в оперативной памяти React (`useState` из `data.js`). После перезагрузки `F5` всё сбрасывалось. | Постоянное хранение в **SQLite** (`subscription-app/server/data/subtrack.sqlite`, таблицы `users`, `sessions`, `subscriptions`, WAL-режим, внешние ключи и автомиграции). |
| **Авторизация и безопасность** | Пользователи и сессия хранились открыто в браузерном `localStorage`. | Серверная регистрация/вход: хеширование паролей через **`scrypt`** с солью и `timingSafeEqual`, серверные сессии в БД (`SHA-256` токен), **`HttpOnly; SameSite=Lax`** cookie, изоляция подписок по `user_id`, защита от перебора паролей (**HTTP 429** rate limit) и защита статики от path traversal. |
| **Стартовые данные** | Статический список одинаковый для всех. | Новые пользователи и существующие пустые аккаунты автоматически получают **8 актуальных примеров подписок** (Netflix, Spotify Premium, YouTube Premium, Cloud Storage, GitHub Copilot, Adobe Creative Cloud, Slack Pro, Notion Plus), плюс кнопка **«Загрузить примеры»** при количестве подписок `< 3`. |
| **Операции с подписками (CRUD)** | Только добавление в память и смена статуса на `cancelled`. | Полный CRUD через REST API: создание (`POST`), поиск и фильтрация по категориям и всем статусам включая отменённые (`GET`), полное редактирование и пауза/возобновление (`PATCH`), кнопка **«Оплачено (+1 мес / год)»** (`POST .../renew` с корректным переносом конца месяца), удаление (`DELETE`) и строгая проверка календарных дат на сервере (отклоняет даты вроде `2026-02-30`). |
| **Аналитика и статистика** | Годовые подписки суммировались как месячные, график динамики был захардкожен. | Точный пересчёт месячного эквивалента (`amount / 12` для годовых), серверный расчёт **`GET /api/insights`** (ближайшие списания, распределение по категориям, потенциальная годовая экономия и практичные рекомендации по оптимизации). |
| **Профиль и экспорт** | Статическая страница настроек без сохранения. | Настройки имени, горизонта напоминаний (`1–30` дней) и детектора неиспользуемых подписок сохраняются в SQLite (`PATCH /api/profile`). Добавлена выгрузка списка подписок в **CSV (UTF-8 BOM)** для Excel. |
| **Запуск и публикация** | Только `vite` dev-сервер. | Запуск **одной командой `npm run dev`** (`dev.mjs` поднимает и Backend `:3001`, и Frontend `:5173`), а также production-сервер **`npm start`** для раздачи `dist/` и API с одного порта (готово для временного HTTPS-туннеля). |

## 🛠️ Стек технологий

- **Frontend:** React 18, React Router DOM v6, Vite (`vite.config.js` с proxy `/api` → `http://127.0.0.1:3001`)
- **Backend:** Node.js 22.13+ / 24+ (только встроенные модули `node:http`, `node:crypto`, `node:sqlite`, `node:fs`, `node:path`)
- **База данных:** SQLite (`subscription-app/server/data/subtrack.sqlite`, исключена из Git в `.gitignore`)
- **Стилизация:** Адаптивный CSS с Media Queries (`index.css`), светлая и тёмная темы, дизайн-система из макетов Figma (палитра `#1E3A8A`, `#10B981`, `#EF4444`)

## 🔌 Основные API-эндпоинты (`server/index.js`)

| Метод и путь | Назначение |
| :--- | :--- |
| `GET /api/health` | Проверка работы сервера и SQLite (`{"ok":true,"database":"sqlite"}`) |
| `POST /api/auth/register` | Регистрация аккаунта, старт cookie-сессии и загрузка 8 стартовых подписок |
| `POST /api/auth/login` | Вход по email и паролю (с rate-limit и автозаполнением примеров для пустых аккаунтов) |
| `POST /api/auth/logout` | Выход и удаление серверной сессии |
| `GET /api/auth/me` | Получение текущего авторизованного пользователя по `HttpOnly` cookie |
| `PATCH /api/profile` | Сохранение имени, срока уведомлений (`1–30` дн.) и флагов в таблицу `users` |
| `GET /api/subscriptions` | Список подписок текущего пользователя с фильтрацией (`status`, `category`, `search`) |
| `POST /api/subscriptions` | Создание новой подписки с валидацией полей и календарной даты |
| `POST /api/subscriptions/seed` | Загрузка недостающих стартовых примеров подписок |
| `GET /api/subscriptions/export` | Экспорт подписок в `.csv` (UTF-8 BOM + защита от CSV-инъекций) |
| `GET / PATCH / DELETE /api/subscriptions/:id` | Просмотр, полное редактирование (в т.ч. пауза/отмена) и удаление подписки |
| `POST /api/subscriptions/:id/renew` | Продление даты следующего списания на `+1 месяц` или `+1 год` |
| `GET /api/insights` | Расчёт месячных/годовых сумм, ближайших списаний, категорий и рекомендаций |

## 📄 Реализованные страницы (7 маршрутов)

1. `/login`, `/register` — **Авторизация и регистрация**: Создание аккаунта и вход с проверкой на сервере и `HttpOnly` cookie-сессией.
2. `/` — **Главная (Dashboard)**: Месячный и годовой эквиваленты расходов, потенциал экономии, предупреждения о ближайших списаниях, рекомендации по оптимизации и сетка подписок.
3. `/subscriptions` — **Мои подписки**: Полный каталог с поиском, фильтрацией по статусам (`Активные`, `На паузе`, `Пробные`, `Отменённые`) и категориям, а также экспорт в CSV.
4. `/add` — **Добавить подписку**: Форма создания новой подписки с выбором категории, периода и даты списания.
5. `/subscription/:id` — **Детали подписки**: Годовая стоимость, полное редактирование всех полей, кнопка **«Оплачено (+1 мес/год)»**, пауза/возобновление, отмена и удаление.
6. `/stats` — **Статистика**: Распределение расходов по категориям (в месячном эквиваленте), прогноз трат и оценка годовой экономии, выгрузка CSV-отчёта.
7. `/profile` — **Профиль пользователя**: Изменение имени, настройка срока уведомлений и детектора редких подписок (сохраняется в SQLite), список авторов проекта.

## 🚀 Как установить и запустить локально

> **Требования:** установлен **Node.js 22.13+** (рекомендуется **Node.js 24 LTS**), так как используется встроенный модуль `node:sqlite`. Проверить версию: `node -v`.

1. Клонируйте репозиторий (или обновите его до последней версии) и перейдите в папку приложения:
   ```bash
   git clone https://github.com/Kirigami001/subscription-guard.git
   cd subscription-guard/subscription-app
   npm install
   ```
   *(Если проект уже скачан ранее, перед запуском обновите код: `git pull origin main`.)*

2. Запустите проект **одной командой** (одновременно запустит Backend на порту `3001` и Frontend на `5173`):
   ```bash
   npm run dev
   ```
   *(При необходимости можно запускать в двух отдельных терминалах: `npm run server` и `npm run client`.)*

3. Откройте в браузере:
   ```text
   http://localhost:5173
   ```
   - Зарегистрируйте аккаунт (или войдите в существующий) — на главном экране сразу появятся примеры подписок.
   - База данных SQLite создаётся автоматически по пути `subscription-app/server/data/subtrack.sqlite` и **не попадает в Git**.
   - Проверить состояние API и SQLite можно по адресу: `http://127.0.0.1:3001/api/health` → `{"ok":true,"database":"sqlite"}`.

## 🌐 Временный публичный доступ (туннель для демонстрации)

Поскольку приложение использует Node.js и локальную базу данных SQLite, его нельзя хостить на статическом GitHub Pages — для временного показа в интернете используется production-режим + временный HTTPS-туннель:

1. В первом терминале соберите и запустите единый сервер (`dist/` + `/api` + SQLite на порту `3001`):
   ```bash
   cd subscription-app
   npm start
   ```
2. Во втором терминале откройте временный HTTPS-туннель к порту `3001`:
   ```bash
   # Вариант 1 (Cloudflare Quick Tunnel, если установлен cloudflared):
   npm run tunnel

   # Вариант 2 (без предварительной установки через npx):
   npx localtunnel --port 3001
   ```
Туннель выдаст временный `https://...` адрес для проверки с другого устройства; ссылка работает, пока ваш компьютер и оба терминала запущены.
